## Одновременные бронирования с PostgreSQL и несколькими экземплярами

- Очередь в памяти работает только внутри одного процесса, для нескольких экземпляров не подходит.
- Вариант 1: exclusion constraint — `EXCLUDE USING gist (master_id WITH =, tstzrange(start, end) WITH &&) WHERE (status = 'active')`. Тогда БД сама не даст сохранить пересекающуюся запись, а ошибку мы превращаем в 409.
- Вариант 2: транзакция с `SELECT ... FROM masters WHERE id = $1 FOR UPDATE` (или `pg_advisory_xact_lock(master_id)`), внутри проверка слота и INSERT.
- Я бы выбрал вариант 1: защита на уровне БД, работает при любом количестве серверов.
